server <- function(input, output) {
  
  output$graded_results <- renderUI({
    # 1. Get the user's cohort from the full dataset
    cohort <- marathon_joined |> 
      filter(Gender == input$user_gender, Age == input$user_age, Year == 2022) |>
      arrange(Finish_Minutes)
    
    # 2. Find user's percentile rank in that cohort
    # We find how many people in their age/year they beat
    rank <- sum(cohort$Finish_Minutes <= input$user_time)
    user_percentile <- round((rank / nrow(cohort)) * 100, 0)
    
    # 3. Pull the "Graded" time from the 2024 Peak lookup
    lookup_table <- if(input$user_gender == "W") women_percentile else men_percentile
    graded_val <- lookup_table$Mean_Time[lookup_table$Percentile == user_percentile]
    
    # Format minutes back to H:MM
    format_time <- function(mins) {
      paste0(mins %/% 60, "h ", sprintf("%02d", mins %% 60), "m")
    }
    
    tagList(
      h4(paste("Your Percentile in Cohort:", user_percentile, "%")),
      h2(paste("Graded Time:", format_time(graded_val))),
      p("This is what you would have run in 2024 if you were 25 years old.")
    )
  })
}

You're right to catch that—the code I just gave you accounts for age and gender, but it doesn't dynamically adjust for temperature across different years. It only "grades" you against the 2024 results, which you identified as having ideal conditions.

To truly "temp-grade" a runner who ran in a different year (like the "worst year," 2022), you need to mathematically bridge the gap between that year's mean performance and the ideal year's performance.

How to add the "Temperature Bridge"
We can calculate a Temperature Offset. This is the difference between the average finish time in a "bad" year (2022) and your "ideal" year (2024).

Calculate the Offset: Find the difference in mean times between 2022 and 2024.

Adjust the Input: Subtract that offset from the user's actual 2022 time before calculating their percentile. This "normalizes" their time as if they had run in the cooler 2024 weather.

    user_percentile <- max(1, min(100, user_percentile))

# Helper function to convert HH:MM string to total minutes
parse_marathon_time <- function(time_str) {
  parts <- as.numeric(unlist(strsplit(time_str, ":")))
  if (length(parts) == 2) {
    return((parts[1] * 60) + parts[2]) # HH:MM
  } else if (length(parts) == 3) {
    return((parts[1] * 60) + parts[2] + (parts[3]/60)) # HH:MM:SS
  }
  return(NA)
}

Why this works:
!important: This is a CSS rule that tells the browser to prioritize this specific color over any other styles defined in the "Flatly" theme.

.container-fluid: Shiny wraps its content in a container that sometimes has its own background color. Targeting both body and .container-fluid ensures the color covers the entire screen.

Hex Codes: I used #f7f9fc (a very light professional blue/grey), but you can change that to any hex code (e.g., #ffffff for pure white or #fff5f5 for a light red).
